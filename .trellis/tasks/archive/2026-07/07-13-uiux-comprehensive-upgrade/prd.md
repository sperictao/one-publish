# UI/UX 全面优化升级：动效层、发布流程、状态完整性与细节收口

## Goal

在已完成 Geist 静态视觉对齐的基线之上，系统性提升 One Publish 的交互体验质量：让界面从「静态规范正确」进化到「交互反馈细腻、核心流程有节奏感、状态覆盖完整、细节无杂音」。

## 需求来源

用户请求：「彻底发挥你的潜力，全面优化升级 UI UX」，经确认四个方向全选：
1. 动效与微交互层
2. 发布核心流程 UX
3. 状态完整性
4. 细节收口 Polish

## 模式判定与约束

- **Redesign - Preserve 模式**：Geist 设计系统（step token、typography 工具类、双主题）已锁定，本轮**不改**配色体系、圆角体系、字体排版规范。所有改动在现有 token 之上叠加。
- 不改信息架构：三栏布局（仓库列表 / 发布配置 / 主内容）、面板折叠/拖拽机制保持不变。
- 不改 i18n key 结构（新增 key 允许，重命名需在子任务 PRD 中单独声明）。
- 所有动效必须遵守 `prefers-reduced-motion`（复用现有 `useReducedMotion`）。
- 只动 `transform` / `opacity` 做动画，禁止动画 layout 属性。
- 桌面产品 UI 场景：动效克制、有目的（层级 / 反馈 / 状态流转），不做营销页式炫技。
- 不引入与现有栈冲突的动画库；如需引入 `motion`，须在子任务 design.md 中论证收益与包体代价。

## 任务地图（子任务）

| 子任务 | 交付物 | 优先级 |
|---|---|---|
| 07-13-uiux-motion-layer | 面板折叠过渡、列表操作动效、按钮 tactile 反馈、弹层出入场统一 | P1 |
| 07-13-uiux-publish-flow | 发布进行中的阶段感知、日志流体验、成功/失败时刻反馈 | P1 |
| 07-13-uiux-state-completeness | 空态/骨架/错误态系统性覆盖，替换通用 spinner 与空 fallback | P2 |
| 07-13-uiux-detail-polish | 焦点环统一、快捷键可发现性、aria 覆盖、间距对齐收口、微文案 | P2 |

执行顺序建议：motion-layer 与 publish-flow 可并行规划但串行实施（publish-flow 会消费 motion-layer 产出的动效原语）；state-completeness 其次；detail-polish 收尾。

## 跨子任务验收标准

- [ ] 四个子任务各自的验收标准全部通过并归档。
- [ ] `pnpm typecheck`、`pnpm test`、`pnpm doctor` 全绿；e2e 关键路径（发布流程 spec）不回归。
- [ ] 开启系统「减弱动态效果」后，所有新增动效退化为瞬时切换，功能无损。
- [ ] 明暗两主题下人工过检一遍全部改动界面，无对比度/层级回归。
- [ ] 动效原语（时长/缓动 token）沉淀为共享定义，四个子任务不各自硬编码时长曲线（DRY）。
- [ ] 最终集成审查：整页体验连贯，无「某个面板动、其他面板跳变」的割裂感。

## Notes

- 各方向的现状事实与缺口清单由 research 代理产出，落在各子任务 research/ 目录，子任务 PRD 基于事实清单编写。
- 本父任务不承担直接实现，只承担需求源、任务地图与最终集成审查。
