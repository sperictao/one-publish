# Store provider release settings in revision parameters

Provider release settings — the publish-time configuration a provider needs beyond its command parameters, such as Tauri's desktop targets, tag prefix, updater, secret names, release gates and version mirrors — live inside the ordinary publish-configuration revision under the reserved parameter key `releaseSettings`. The key is not a command parameter: command rendering, parameter matching and the parameter editor all ignore it, and updates that omit it inherit the current revision's value for the same provider so ordinary parameter edits cannot silently erase the settings, while an explicit `null` clears them and a provider switch drops them. The legacy per-repository Tauri store (`tauri-release.json`) is merged into the catalog once at startup and removed only after every entry is merged and persisted; entries for unknown repositories are dropped, matching how deleting a repository already discards its configurations, and the retired release-center UI, its fourteen dedicated commands and its private attempt store are deleted without a compatibility path, which leaves the settings read-only in the UI until the schema-driven editor arrives. This is the interim shape on the way to ADR-0030: settings are versioned by the revision's existing `settingsVersion` and migrate to per-adapter schemas in a later step instead of keeping a second store alive; ADR-0003's rule that the configuration catalog is the only editable authority stays intact.
