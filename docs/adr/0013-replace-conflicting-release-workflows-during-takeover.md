# 发布接入必须替换冲突的旧 workflow

One Publish 接入目标仓库时会扫描可能响应相同版本标签或创建相同 GitHub Release 的既有 workflow，检测到冲突就阻止继续，避免重复构建或争抢版本。使用者确认完整差异后，一个接入提交同时移除或停用所选冲突流程并加入独立托管流程；此后 One Publish 只维护自己的生成文件，不冲突的 quality、test 等 workflow 保持不变。

接入提交由 One Publish 在完整 diff 确认后直接推送到检测出的远端默认分支。分支保护或权限拒绝时保留接入未完成状态并返回原始 Git 错误，修复后允许重试；首版不自动创建 PR，也不绕过分支保护。
